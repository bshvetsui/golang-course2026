## sync.Mutex - блокирует все горутины кроме одной. Разблокировать должна та же горутина что и заблокировала
1. Lock() - сделать блокировку
2. Unlock()  - разблокировать
3. TryLock() - попробовать блокнуть, если занята - вернет false
   ```
   type Mutex struct {
    state int32 // числовое(битовое) значение состояния см. ниже 
    sema  uint32 // идентификатор для gopark/goready. Называется семафор
}
   ```
![[{photo_2026-07-26_17-57-32.jpg|490]]
Режим голодания включается, если горутина ждет Mutex долго (1мс+) он передает Mutex напрямую. Можно глянуть Mutex.state чтобы убедится что он вкл или выкл. Normal mode намного быстрее.
## sync.RWMutex() - Много читателей могут работать одновременно.  Но когда появляется писатель, он получает эксклюзивный доступ — все ждут пока он закончит.
Использовать когда читают часто, а пишут редко
```
type RWMutex struct {
    w           Mutex //внутренний Mutex, гарантирующий что писать может только 1 writer
    writerSem   uint32 // семафор для парковки и пробуждения ожидающего писателя
    readerSem   uint32 // семафор для парковки и пробуждения читателей
    readerCount atomic.Int32 //кол-во активных читателей. Если отриц -> писатель уже ждет или владеет блокировкой
    readerWait  atomic.Int32 // сколько читателей должно закончить работу, прежде чем можно разбудить писателя
}
```
1. RLock()  - захват для чтения. Атомарно увеличивается счетчик читателей, если счетчик стал отриц. - кто то хочет читать, и читатель засыпает пока тот не закончит
2. RUnlock()  - атомарно уменьшаем счетчик читателей 
3. Lock() - для записи захватывает Mutex w и readerCount делает отрицательным 
4. Unlock() - возвращаем как было

## sync.WaitGroup - ждет пока все горутины завершаться
```
type WaitGroup struct {
    noCopy noCopy
    state  atomic.Uint64 // тут 2 счетчика, 1ые 32-кол-во незавершенных задач, 2ые сколько горутин спит под Wait()
    sema   uint32 // семафор 
}
```
1. Add(n) - говорим сколько горутин будем ждать. Вызывать до запуска G или будет гонка
2. Done() - горутина сообщает что закончила
3. Wait() - блокируемся пока все не вызовут Done()
Нельзя чтобы счетчик становился отрицательным, будет паника

## sync.Once - код выполнится **ровно один раз**, даже если его одновременно вызовут сотни горутин
Используется для открытия соединения с БД и не только. 
```
type Once struct {
	done atomic.Bool // false - не выполнялось, true - уже выполнено, проверяется атомарно без блокировок. Если функция паникует все равно поставится true 
	m    Mutex
}
```
double-check - done проверяется дважды - быстро и с мьютексом чтобы наверняка
1. Do(f) - выполнить функцию. Если функция паникует все равно 

## sync.Pool - переиспользует объекты которые часто создаются или быстро становятся ненужными. 
Нужно чтобы не делать частую аллокацию памяти. GC может в любой момент очистить эти объекты, здесь нельзя ничего хранить
```
type Pool struct {  
noCopy noCopy  
local unsafe.Pointer // массив poolLocal, по одному на каждый P  
localSize uintptr  
victim unsafe.Pointer // объекты с прошлого цикла GC  
victimSize uintptr  
New func() any  
}  
  
type poolLocal struct {  
private any // личный объект этой P  
shared poolChain // очередь объектов, доступная другим P  
}
```
1. Get() - взять объект из пула и создать новый
2. Put(x) - вернуть объект в пул для переиспользования
## sync.Cond - позволяет одним горутинам ждать наступления события, а другим сообщать, что событие произошло.
Его всегда используют вместе с Mutex
```
type Cond struct {
    noCopy noCopy
    L      Locker // Связанный Mutex
    notify notifyList // список ожидающих
}
```
1. Wait() -ждёт наступления условия. Запускать нужно в цикле
2. Signal() - будит ОДНУ ожидающую горутину в порядке FIFO
3. Broadcast() - будет всех ожидающих
На практике каналы чаще удобнее. Закрытие канала работает как Broadcast(), отправка в канал работает как Signal - просыпается один.

## sync.Map - потокобезопасная map. 
Использовать когда ключи стабильны. map + sync.RWMutex намного чаще используется
```
type Map struct {  
mu Mutex  
read atomic.Pointer[readOnly] // доступ без блокировки  
dirty map[any]*entry // полная версия, требует блокировки  
misses int // счётчик промахов  
}  
  
type readOnly struct {  
m map[any]*entry  
amended bool // true если в dirty есть ключи, которых нет в read  
}  
  
type entry struct {  
p atomic.Pointer[any] // указатель на значение  
}
```
1. Load(key) - получить значение
2. Store(key, value) - записать значение 
3. Delete(key) - удалить
4. Range(f) - пройтись по всем ключам функцией
