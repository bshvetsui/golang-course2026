## ALTER TABLE - Изменяет структуру существующей таблицы.
```sql
ALTER TABLE users ADD COLUMN age INT;
ALTER TABLE users DROP COLUMN age;
ALTER TABLE users RENAME COLUMN name TO username;
ALTER TABLE users ALTER COLUMN age SET NOT NULL;
```
⚠️ `ALTER TABLE` может **заблокировать таблицу** на время операции. 
#  CREATE TRIGGER trigger_name — автоматически запускает функцию при изменении данных.
```sql
CREATE TRIGGER update_trigger
BEFORE UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION update_user();
```
События: `INSERT`, `UPDATE`, `DELETE`.

Используют для аудита, автоматического обновления полей и т.п.
#  Подзапрос WHERE EXISTS — SQL внутри другого SQL.
```sql
SELECT *
FROM users
WHERE id IN (
    SELECT user_id FROM orders
);
```
`EXISTS` проверяет: **нашёл внутренний запрос хотя бы одну строку или нет**.
```sql
SELECT *
FROM users u
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.user_id = u.id
);
```
Часто используют для проверки наличия связанных данных.
# NULLIF - Возвращает `NULL`, если два значения равны.
```sql
NULLIF(a, b)
```
Пример защиты от деления на `0`:
```sql
price / NULLIF(count, 0)
```
## CREATE FUNCTION  func_name() - сохранённая логика в БД, которую можно вызывать из SQL
```sql
CREATE FUNCTION add(a INT, b INT)
RETURNS INT
AS $$
    SELECT a + b;
$$ LANGUAGE SQL;

SELECT add(2, 3);
```
Удобно для переиспользуемой логики рядом с данными, но сложную бизнес-логику обычно лучше держать в приложении.
# CREATE VIEW — сохранённый `SELECT`.
```sql
CREATE VIEW active_users AS
SELECT *
FROM users
WHERE active = true;

SELECT * FROM active_users;
```
Данные отдельно **не хранятся** — при обращении выполняется запрос к исходным таблицам.
# CREATE MATERIALIZED VIEW - результат запроса физически хранится
```sql
CREATE MATERIALIZED VIEW stats AS
SELECT country, COUNT(*)
FROM users
GROUP BY country;
```
Читать быстрее, но данные могут устареть.
Обновление:
```sql
REFRESH MATERIALIZED VIEW stats;
```
`VIEW` → всегда свежие данные.  
`MATERIALIZED VIEW` → быстрее чтение, но нужно обновлять. Обычно делают раз в день cron'ом в postgreSQL
# JSONB
`JSONB` — хранение JSON внутри PostgreSQL.
```sql
{"name": "Alex", "age": 25, "address": {"city": "Moscow"}}
```
Если колонка называется `data`:
```sql
data->'name'              -- JSON значение
data->>'name'             -- текст
data->'address'->>'city'  -- вложенное значение
```
Фильтрация:
```sql
WHERE data->>'name' = 'Alex'
WHERE (data->>'age')::INT >= 18
```
Проверка содержимого:
```sql
WHERE data @> '{"name":"Alex"}'
```
Для `JSONB` можно создавать GIN-индексы, чтобы ускорять поиск по JSON.
