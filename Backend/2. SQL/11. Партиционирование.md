Это деление одной таблицы на части, логически обусловленные.
Нужно чтобы уменьшить индексы каждой партиции, и чтобы некоторые SELECT были легче, например удаление таблицы за 2025 год. При этом для приложения это всё ещё выглядит как одна таблица:
```
orders
├─ orders_2025
├─ orders_2026
└─ orders_2027
```
Партиционирование удобно, когда данные естественно делятся:
```
logs      → по дате
events    → по дате
orders    → по месяцу/году
metrics   → по времени
customers → иногда по tenant_id
```

Частным случаем партиционирования является Шардирование, это деление данных на несколько БД.
