## Window functions / OVER

Оконные функции считают значения по группе строк, **но не схлопывают строки**, как `GROUP BY`.
```sql
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (PARTITION BY department)
FROM employees;
```
1. `OVER()` — делает функцию оконной.
2. `PARTITION BY` — делит строки на группы.
3. `ORDER BY` внутри `OVER` — задаёт порядок внутри группы.
Частые функции:
```sql
ROW_NUMBER() OVER (ORDER BY salary DESC)
SUM(price) OVER (PARTITION BY user_id)
AVG(salary) OVER (PARTITION BY department)
```
`GROUP BY` → одна строка на группу.  
`OVER` → исходные строки остаются.
# CTE — WITH  var_name AS
CTE — временный именованный результат запроса, чтобы разбить сложный SQL на части.
```sql
WITH expensive_orders AS (
    SELECT *
    FROM orders
    WHERE price > 1000
)
SELECT *
FROM expensive_orders;
```
Можно использовать несколько:
```sql
WITH a AS (...),
     b AS (...)
SELECT ...
```
# Transactions
Транзакция — несколько операций, которые выполняются как одно целое.
```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```
1. `BEGIN` — начать транзакцию.
2. `COMMIT` — сохранить изменения.
3. `ROLLBACK` — отменить все изменения транзакции.
# CASE WHEN
Условие внутри SQL — аналог `if/else`.
```sql
SELECT
    name,
    CASE
        WHEN age >= 18 THEN 'adult'
        ELSE 'child'
    END AS status
FROM users;
```
Можно несколько условий:
```sql
CASE
    WHEN score >= 90 THEN 'A'
    WHEN score >= 70 THEN 'B'
    ELSE 'C'
END
```
`CASE WHEN` сам по себе нормален, но **сложную бизнес-логику обычно лучше держать в приложении** — большое количество такой логики в БД усложняет поддержку и может стать антипаттерном.
## Constraints — ограничение на данные в таблице, которое PostgreSQL проверяет автоматически.
1. `PRIMARY KEY` — уникальный идентификатор строки, автоматически `UNIQUE + NOT NULL`.
2. `FOREIGN KEY` — требует, чтобы значение существовало в другой таблице.
3. `UNIQUE` — запрещает повторяющиеся значения.
4. `NOT NULL` — запрещает `NULL`.
5. `CHECK` — проверяет условие, например `age >= 18`.
6. `EXCLUDE` — запрещает строки, которые конфликтуют по заданному правилу; используется реже, например для пересекающихся диапазонов дат.
Пример:
```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    age INT CHECK (age >= 18),
    role_id BIGINT REFERENCES roles(id)
);
```
При нарушении constraint `INSERT` или `UPDATE` завершится ошибкой.
