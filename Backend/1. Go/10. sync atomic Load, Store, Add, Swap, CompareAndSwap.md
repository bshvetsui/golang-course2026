На x86 используются инструкции:
1. `LOCK XADD` — `Add`
2. `LOCK CMPXCHG` — `CompareAndSwap`
3. `XCHG` — `Swap`
4. `MOV` — `Load`/`Store` (с нужными memory barrier)
## CAS-цикл
Lock-free алгоритмы обычно работают так: читают значение → вычисляют новое → пытаются записать через `CompareAndSwap`. Если за это время значение изменилось, операция повторяется.
При низкой конкуренции это быстрее `Mutex`, при высокой — постоянные повторы могут сделать `Mutex` эффективнее.
## Memory ordering
Go использует **Sequential Consistency** — все горутины наблюдают атомарные операции в одном порядке. Компилятор и CPU не могут переупорядочить обычные операции через атомарные.
## Кэш-когерентность
У каждого ядра есть собственный кэш. При атомарной записи процессор синхронизирует кэш с другими ядрами (протокол **MESI**).
Если несколько ядер постоянно изменяют один атомик, кэш-линия начинает постоянно переходить между ними (**cache line bouncing**), из-за чего производительность падает.
## Основные операции
Раньше (до go 1.19 писалось сложнее например atomic.LoadInt64, но сейчас проще)
1. `atomic.Load()` — атомарное чтение.
2. `atomic.Store()` — атомарная запись.
3. `atomic.Add()` — атомарное прибавление.
4. `atomic.Swap()` — атомарная замена с возвратом старого значения.
5. `atomic.CompareAndSwap() (CAS)` — заменить значение, только если оно ещё равно ожидаемому. Основа lock-free алгоритмов. 
## atomic.Value
Позволяет атомарно хранить значение любого типа.
После первого `Store` тип фиксируется. Если записать другой тип — будет panic.
Обычно используется для атомарной замены конфигурации или других редко изменяемых данных.
## Atomic vs Mutex
**Atomic** подходит для:
счётчиков; флагов; указателей; простых lock-free структур.
**Mutex** нужен, когда: 
изменяется несколько связанных полей; требуется сложная критическая секция.
