### 1. Rolling Update (90% релизов)
DevOps просто обновляет обычный `Deployment`:
`v1 v1 v1 → v2 v1 v1 → v2 v2 v1 → v2 v2 v2` 
### 2. Canary
   DevOps **не заменяет сразу всю v1**, а запускает v2 параллельно и меняет процент трафика. Можно использовать 
   Argo rollout (легковесный, нужен только для этого) или 
   Istio (тяжелая штука, используются сразу для многих разных задач, тянуть для только для роллаута - глупо)
   Argo rollout делается через конфиг в helm:
``` yaml
   helm/
├── Chart.yaml
├── values.yaml
├── values-prod.yaml
└── templates/
    ├── rollout.yaml       ← ВОТ ЗДЕСЬ
    ├── service.yaml
    ├── ingress.yaml
    └── configmap.yaml
    
strategy:
  canary:
    steps:
      - setWeight: 5
      - pause: {}
      - setWeight: 20
      - pause: {}
      - setWeight: 50
      - pause: {}
``` 
чтобы увидеть что деплой реально пошел:
`kubectl argo rollouts get rollout order-api -w
Увидит примерно:
`Stable: v1`  
`Canary: v2`  
`Weight: 5%`  
`Status: Paused`

Параллельно открывает **Grafana** и смотрит ошибки/latency новой версии.

### 3. Feature Toggle
Выкатывается обычный Deployment без новой фичи, которую можно включить по  значению через .env или через сторонюю админку.
После успешного deploy DevOps/Lead открывает, например, **Unleash / LaunchDarkly**:  
`new-payment → OFF → 5% → 20% → 100%`  
Если функция ломается:  
`100% → OFF`
## 4. Blue-Green
поднять вторую полную версию → проверить → одним переключением перенаправить весь трафик через ingress.
