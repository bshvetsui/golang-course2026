Каждый `ReactiveEffect` может иметь функцию `scheduler`. У Render Effect она всегда есть. Поэтому `trigger()` не вызывает `effect.run()`, а вызывает `effect.scheduler()`.

Стандартный scheduler компонента вызывает `queueJob(instance.update)`. `instance.update` — это функция обновления компонента, внутри которой вызывается `effect.run()`.

`queueJob()` помещает задачу в глобальную очередь `queue`. Если такая задача уже находится в очереди, повторно она не добавляется. Проверка выполняется по ссылке на функцию, поэтому один компонент не может оказаться в очереди несколько раз за один цикл обновления.

Если очередь еще не запланирована к выполнению, `queueJob()` вызывает `queueFlush()`. Эта функция создает один `Promise.resolve().then(flushJobs)`, тем самым перенося выполнение очереди в ближайший **microtask**.

Когда начинается `flushJobs()`, очередь сортируется по `job.id`. Для Render Effect этим идентификатором является `instance.uid`, который увеличивается при создании компонентов. Поскольку родители создаются раньше детей, их `uid` меньше, следовательно, родительские компоненты обновляются раньше дочерних.

Во время выполнения `flushJobs()` последовательно вызываются все `job()`. Для компонента это приводит к вызову `instance.update()`, затем `effect.run()`, после чего выполняется `render()`, строится новое дерево `VNode` и запускается `patch()`.

Если во время выполнения `flushJobs()` очередной `trigger()` добавляет новые задачи, они помещаются в конец очереди. После завершения текущего прохода `flushJobs()` проверяет, остались ли необработанные задачи или post-flush callback'и. Если очередь снова стала непустой, выполнение продолжается без создания нового microtask.

Кроме основной очереди существует очередь **pre-flush callbacks** (`queuePreFlushCb`) и **post-flush callbacks** (`queuePostFlushCb`). Первая выполняется до обновления компонентов и используется, например, для `watch` с `flush: 'pre'`. Вторая выполняется после завершения всех `patch()` и используется для `watch` с `flush: 'post'`, lifecycle-хуков вроде `onUpdated()` и обработки `nextTick()`.

Таким образом полный путь выглядит так:

`trigger()` → `effect.scheduler()` → `queueJob()` → `queueFlush()` → `flushJobs()` → `instance.update()` → `effect.run()` → `render()` → `patch()`.
