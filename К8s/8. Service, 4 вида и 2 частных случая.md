встроенный API-ресурс, который предоставляет стабильную сетевую точку доступа к подам. Обычно реализован внутренним **kube-proxy**
через ServiceIP можно получить доступ к подключенным к нему подам
`Service IP → Pod A / Pod B / Pod C`
создание:
``` yml
kind: Service # выбираем сервис
spec:
  selector:
    app: backend # определяет какие поды будут подключены к сервису

  ports:
    - port: 80 # ПОРТ СЕРВИСА
      targetPort: 8080 # ПОРТ ПОДОВ в сервисе
      
  type: ClusterIP # тип по умолчанию, всего их 4:
```
### 1. ClusterIP
k8s выделяет Service виртуальный IP из диапазона Service'ов, этот адрес доступен только внутри кластера. ПО УМОЛЧАНИЮ
```Pod
 │
 │ GET backend:80
 ▼
IP Servicе'а
10.96.5.10:80
 │
 ├── Pod A:8080
 ├── Pod B:8080
 └── Pod C:8080
```
### 2. NodePort
Через ip любой ноды можно обратится к подам в сервисе
```
192.168.1.10:30080   Node 1
192.168.1.11:30080   Node 2
192.168.1.12:30080   Node 3
          │
          ▼
       Service
          │
          ▼
     один из Pod'ов
```

``` yml
kind: Service
spec:
  type: NodePort

  selector:
    app: backend

  ports:
    - port: 80
      targetPort: 8080
      nodePort: 30080 # В отличии от ClusterIP добавился порт каждой ноды
```
### 3. LoadBalancer
Нужен чтобы балансировать нагрузку по подам с помощью внешних механизмов облаков. В 90% случаев строится поверх NodePort
```
kind: Service
spec:
  type: LoadBalancer
```
### 4. ExternalName
Нужен чтобы подключать внешнюю БД или другие вынесенные из кластера части, просто чаще всего выносят хранилища.
По сути простая подмена url базы на внутреннюю переменную. Делается через cname, cname - это алиас ДНС.
```yml
kind: Service
metadata:
  name: database # мы даем k8s и всем приложениям использовать это имя
spec:
  type: ExternalName
  externalName: postgres.company.internal # вместо этого
```
## 2 Частных случая
### Service без селектора
Если оставить без селектора то у нас будет сервис который не знает куда идти.
```yml
kind: Service
metadata:
  name: potsgres # Мы будем это использовать имя 
spec:
  ports:
    - port: 5432 # C этим портом
```
НО! Если в другом .yaml файле создать EndpointSlice с его айпишником то в кластере мы можем использовать его как `postgres:5432`
```yml
apiVersion: discovery.k8s.io/v1
kind: EndpointSlice
metadata:
  name: legacy-api-1
  labels:
    kubernetes.io/service-name: postgres # Тут мы его привязываем

addressType: IPv4

ports:
  - name: http
    protocol: TCP
    port: 8080

endpoints:
  - addresses:
      - "0.0.0.1" # Его айпишник 
```
### Headless Service
Когда приложению важно знать отдельные экземпляры, например у некоторых stateful-систем (например, конкретная БД из ее 3ех подов).
``` yml
apiVersion: v1
kind: Service
metadata:
  name: postgres
spec:
  clusterIP: None # мы не пишем type: а пишем вот это

  selector:
    app: postgres

  ports:
    - port: 5432
```
