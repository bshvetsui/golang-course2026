# controller manager 
состоит из 50 контроллеров, например ReplicaSetController, DeploymentController и т.д. Каждый следит за своими схемами, часть держит в ОЗУ (кэши/**informers**), а если там нет смотрит в **etcd**. Если под упал - вызывает **KubeAPI** для пересоздания пода.

**Контроллерные ресурсы** - это те самые схемы контроллеров
### ReplicaSet 
Она запускает определенное количество подов и если какие то упали, перезапускает. ![[Pasted image 20260813125811.png|271]]
в .yaml кубера выглядит так
```yml 
kind: ReplicaSet # выбираем ReplicaSet
spec:
  replicas: 2 # количество контейнеров
```
### Deployment
механизм обновления подов с помощью репликасетов. 90% всех приложений (фронтенд, ,бекенд) крутится на нем
![[Pasted image 20260813132153.png|655]]
2 стратегии:
1. **Recreate** - При модификации деплоймента РЕПЛИКАСЕТ ПОЛНОСТЬЮ УДАЛЯЕТСЯ и создается новый с новыми настройками
2. **RollingUpdate** - ПОДЫ УДАЛЯЮТСЯ в одном ReplicaSet, в новом создаются. И это регулируется параметрами maxSurge, maxUnavailable - лимит превышения и недоступности . ReplicaSet не удаляются, они будут пустыми и будут историей изменений.
```
kind: Deployment
spec:
  replicas: 2 # количество контейнеров
  strategy:
    type: Recreate # стратегия обновления
  selector: app=backend # ищет во всём k8s все поды с app:backend и применяет деплой на них
```
### statefullSet
1. Есть PVC у каждого пода (возможность писать в диск сервера где k8s стоит) 
2. Используется для баз данных или чего то что хранит данные. Потому что если упадет - то перезапустится с теми же данными. Deployment так не может, на всех их во всем кластере один PVC.
3. Также statefulset не перебросится на другую ноду, как Deployment, и Replicaset - их поды раскидывает **kube scheduler** по нодам чтобы распараллелить нагрузку. 
4. Если мы убиваем его процесс в линуксе (SIGTERM'ом), то он будет висеть некоторое время, потому что поток данных внутри базы нужно остановить.
### daemonSet
Висит один на каждой ноде, сразу при запуске всего кластера. Типо как службы в виндусе. Нужен для сбора логов с помощью **filebeat** и прочих beat-агентов. там же крутится kube-proxy, так же могут стоять Cilium или Calico, это CNI плагины самые популярные.
