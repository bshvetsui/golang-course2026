### Как делать JOIN между shards?
Представь:
```
users → shard-1
orders → shard-3
```
PostgreSQL на `shard-1` не может просто сделать обычный:

```
SELECT *
FROM users
JOIN orders ...
```
потому что `orders` физически на другом сервере.

Поэтому **лучшее решение — проектировать shard key так, чтобы связанные данные лежали вместе**:
```
shard_key = user_id

shard-1:
user 42
orders user 42
payments user 42
addresses user 42
```

Тогда обычный JOIN происходит локально:
```
users
JOIN orders
```
на одном PostgreSQL.

Если JOIN действительно cross-shard, варианты:
1. Получить данные с нескольких shards и соединить в Go.
2. Сделать fan-out query по shards и агрегировать результат.
3. Использовать distributed DB/sharding layer вроде Citus, который умеет часть этого делать сам.
4. Денормализовать данные.
**В хорошем sharding design cross-shard JOIN стараются минимизировать.**
### 8. Как делать transaction между shards?
Внутри одного shard всё просто:

```
BEGIN

UPDATE users ...
INSERT orders ...

COMMIT
```
Но:
```
shard-1:
UPDATE account A

shard-2:
UPDATE account B
```
это уже **distributed transaction**.

Обычный PostgreSQL `BEGIN/COMMIT` не объединит две независимые БД.
Варианты:
1. **Избегать** — лучший вариант. Держать транзакционно связанные данные на одном shard.
2. `2PC` / two-phase commit — сначала все shards `prepare`, потом общий `commit`. Сложно и имеет свои operational-проблемы.
3. **Saga** — несколько локальных транзакций + компенсация при ошибке. Часто используется на уровне приложения/сервисов.
4. Event-driven схема через broker/outbox, если мгновенная атомарность не требуется.
Поэтому снова видно, насколько важен shard key:
```
один user/tenant
       ↓
один shard
       ↓
обычная PostgreSQL transaction
```
## Уникальность ID
Автоинкремент не работает через шарды. Решения:

- **UUID** — универсально уникальный, но большой и неупорядоченный
- **Snowflake ID** — timestamp + machine_id + sequence. Упорядоченный и компактнее UUID
- **Централизованный генератор** — единая точка выдачи ID
- **Диапазоны** — каждый шард получает свой диапазон ID
