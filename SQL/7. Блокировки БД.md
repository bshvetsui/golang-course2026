### 1. Блокируется строка - когда меняются конкретные записи:
1. `UPDATE` — блокирует изменяемые строки.
2. `DELETE` — блокирует удаляемые строки.    
3. `SELECT ... FOR UPDATE` — специально блокирует выбранные строки.
4. `SELECT ... FOR NO KEY UPDATE / FOR SHARE / FOR KEY SHARE` — более слабые варианты row lock.

Пример: `UPDATE users SET balance = 100 WHERE id = 5;` — блокируется `users.id = 5`, остальные строки обычно доступны.
### 2. Блокируется таблица
Некоторые операции требуют сильной блокировки таблицы:
1. `ALTER TABLE` — **часто `ACCESS EXCLUSIVE`**, может заблокировать и чтение, и запись.
2. `DROP TABLE` — полностью блокирует таблицу.
3. `TRUNCATE` — полностью блокирует таблицу.
4. `VACUUM FULL` — полностью блокирует таблицу.
5. `REINDEX TABLE` — обычный вариант может сильно блокировать таблицу.
6. `LOCK TABLE ... IN ACCESS EXCLUSIVE MODE` — явная полная блокировка.
7. `CREATE INDEX` без `CONCURRENTLY` — блокирует запись в таблицу, но чтение обычно разрешено.

Важно: обычные `INSERT/UPDATE/DELETE` тоже получают **table-level lock**, но слабый — он нужен для координации и обычно **не запрещает другим транзакциям работать с другими строками**.
### 3. Блокируется вся БД
Ближе всего к блокировке всей БД:
1. `DROP DATABASE` — требует отключить остальные подключения к этой БД.
2. Некоторые административные операции могут запрещать новые подключения.
3. `ALTER DATABASE ... ALLOW_CONNECTIONS false` — запрещает новые подключения.
4. `pg_terminate_backend()` можно использовать, чтобы принудительно выгнать текущие подключения.
5. Остановка/рестарт PostgreSQL — фактически делает недоступным весь instance, то есть вообще все БД на сервере.

Коротко запомнить: **`UPDATE/DELETE → строки`, `ALTER/DROP/TRUNCATE/VACUUM FULL → таблица`, вся БД блокируется почти только административными операциями.**
