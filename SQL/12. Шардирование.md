### Shard key — поле, по которому определяется, в какой shard положить запись. 
Выбор shard key — одна из самых важных частей шардирования. Хороший ключ:
1. Равномерно распределяет данные, не создаёт один «горячий» shard.
2. Часто присутствует в запросах.
# Способы шардирования
### 1. Range sharding - делим диапазонами
типо от 0 до 1млн, от 1млн до 2млн и т.д.
в go приложении можно сделать простым роутером
``` go
func shardFor(userID int64) int {
	switch {
	case userID <= 1_000_000:
		return 1
	case userID <= 2_000_000:
		return 2
	default:
		return 3
	}
}
```

Плюс — range-запросы удобные. Минус — можно получить hot shard: данные постоянно будут идти в какой-нить особо активный шард и он переполнится
### 2.Hash sharding
**hash-функция** = функция, которая превращает данные произвольного вида в число фиксированного размера.
```
"user-42" → hash → 291847261
"hello"   → hash → 983472931
"abc"     → hash → 128371923
```
Распределяется по остатку деления хэша на число шардов 
```
11 % 3 → shard-2
10 % 3 → shard-1
 9 % 3 → shard-0
```
Плюс — данные распределяются равномернее.
Главный минус - порядок ломается при добавлении нового shard'а:
```
было:
10 % 3 → shard-1

стало:
10 % 4 → shard-2
```
### 3. Consistent Hashing
Серверы и ключи размещаются на виртуальном кольце (0 до 2^32). Ключ идёт на ближайший сервер по часовой стрелке.

Проблемы:
**Неравномерность** — серверы распределены неравномерно на кольце, один сервер может получить больше данных
**Каскадное падение** — при падении сервера вся его нагрузка переходит на следующий сервер по кольцу. Если тот не выдерживает — падает тоже, нагрузка идёт дальше. Серверы падают как домино
## Virtual Nodes (Virtual Buckets)
Без virtual nodes:
```
Shard A → 1 точка на кольце
Shard B → 1 точка
Shard C → 1 точка
```
Проблема: точки могут случайно распределиться неровно, и один shard получит слишком большой кусок кольца.

С virtual nodes:
```
Shard A → A1, A2, A3, A4...
Shard B → B1, B2, B3, B4...
Shard C → C1, C2, C3, C4...
```
То есть **одна физическая БД представлена на кольце много раз**.
## Преимущества Virtual Nodes
- Равномерное распределение данных
- При добавлении или удалении сервера перемещается ~1/N данных
- Мощным серверам можно давать больше виртуальных нод
- Нагрузка упавшего сервера распределяется между всеми, а не одним — нет каскадного падения
