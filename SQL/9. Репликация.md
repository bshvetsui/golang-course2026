## Главная проблема — **replication lag**. Например:
```
POST /user
→ записали user в primary

сразу:
GET /user
→ запрос ушёл на replica
→ replica ещё не получила изменение
→ user "не найден"
```
Поэтому запросы, где нужен **read-after-write consistency**, тоже некоторое время отправляют на primary.
## PgBouncer
Установка нового соединения с БД — дорогая операция (время и ресурсы CPU). Множество подов Kubernetes генерируют тысячи соединений, что перегружает PostgreSQL. PgBouncer держит пулл открытых соединений, и если текущее разорвется - перенаправляет на уже открытое.
# Как распараллелить чтение в приложении Go
в Go, используя либу pgxpool:
``` go
writeDB, _ := pgxpool.New(
    ctx,
    "postgres://user:pass@postgres-write:5432/db",
)

readDB, _ := pgxpool.New(
    ctx,
    "postgres://user:pass@postgres-read:5432/db",
)
```
