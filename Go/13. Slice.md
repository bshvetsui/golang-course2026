**Slice** — динамическая коллекция элементов. Сам slice не хранит данные, а ссылается на массив фиксированного размера.
**underlying array** — это обычный массив, в котором реально лежат элементы slice
## Структура slice

Slice состоит из трёх полей:
1. `array` — указатель на underlying array.
2. `len` — количество доступных элементов.
3. `cap` — capacity, сколько элементов помещается от начала slice до конца массива.
На 64-битной системе slice header занимает 24 байта.

## Array и slice

1. Array имеет фиксированный размер: `[3]int`.
2. При передаче array копируется целиком.
3. Slice имеет динамическую длину: `[]int`.
4. При передаче slice копируется только его header, а данные остаются общими.
## Примеры создания

1. `var s []int` // nil slice, `len=0`, `cap=0`.
2. `s := []int{1, 2, 3}` // `len=3`, `cap=3`.
3. `s := make([]int, 5)` // пять элементов со значением `0`.
4. `s := make([]int, 0, 10)` // пустой slice с заранее выделенной памятью на 10 элементов.

Предварительное выделение capacity уменьшает количество аллокаций при `append`.

## Как работает append
**append** — встроенная функция Go, которая добавляет элементы в конец slice

Если `len < cap`, новый элемент записывается в существующий массив.
Если места нет:
1. Runtime вычисляет новый capacity.
2. Выделяет новый массив.
3. Копирует в него старые элементы.
4. Возвращает slice, указывающий на новый массив.

Поэтому результат `append` всегда нужно сохранять в переменную:
`s = append(s, value)`

После расширения старый и новый slice могут указывать на разные массивы.

## Рост capacity

1. Для небольших slice capacity обычно растёт примерно в два раза.
2. Начиная с размера около 256 элементов рост постепенно уменьшается и стремится примерно к 25%.
3. Точное значение capacity может отличаться, потому что аллокатор округляет размер выделяемой памяти.
4. На конкретные значения capacity лучше не полагаться.
## Подслайсы

Выражение `s2 := s[1:3]` не создаёт новый массив.

`s` и `s2` указывают на общие данные, поэтому изменение элементов через один slice может быть видно через другой.

У нового slice:

1. `len = high - low`.
2. `cap = cap(s) - low`.

Полная форма `s[low:high:max]` позволяет ограничить capacity:

`s2 := s[1:3:3]`

После этого `append` не сможет перезаписать элементы исходного slice за указанной границей и при необходимости создаст новый массив.

## Копирование

`copy(dst, src)` копирует минимум из `len(dst)` и `len(src)` элементов.
Чтобы получить независимый slice:
`dst := make([]int, len(src))`
`copy(dst, src)`

В новых версиях Go также можно использовать:
`dst := slices.Clone(src)`
## nil и пустой slice

1. `var s []int` // nil slice.
2. `s := []int{}` // пустой, но не nil slice.
3. У обоих `len=0` и `cap=0`.
4. Оба можно использовать с `append`, `range`, `len` и `cap`.

Главные различия:

1. `nilSlice == nil` возвращает `true`.
2. Пустой slice обычно не равен `nil`.
3. При JSON-сериализации nil slice превращается в `null`, а пустой — в `[]`.

## Удержание памяти

Маленький подслайс(slice, созданный из части другого slice) может удерживать в памяти большой underlying array.
Например, slice из 10 элементов может продолжать удерживать массив на несколько мегабайт.
Чтобы освободить исходный массив, нужные данные копируют:

`small := slices.Clone(big[:10])`

После этого `small` хранится в отдельном массиве.
## Передача в функцию

1. Slice передаётся по значению, но копируется только его header.
2. Функция может менять существующие элементы, потому что underlying array общий.

3. Изменение `len` и `cap` внутри функции не изменяет slice вызывающего кода.

Если функция использует `append`, новый slice нужно вернуть:

`func add(s []int, value int) []int {`
`return append(s, value)`
`}`

Использование:
`s = add(s, 10)`
## Escape analysis

Escape analysis определяет, где хранить underlying array slice: на стеке или в heap.
1. Если slice используется только внутри функции, массив может остаться на стеке.
2. Если slice возвращается из функции, передаётся через интерфейс или сохраняется там, где переживёт вызов функции, массив обычно перемещается в heap.
3. Размер тоже важен: `make([]int, 0, 10)` компилятор может разместить на стеке, потому что размер известен заранее.
4. `make([]int, 0, n)` обычно попадает в heap, если значение `n` неизвестно во время компиляции.
Стек быстрее и не создаёт дополнительной работы для GC. Объекты в heap контролируются сборщиком мусора.
Проверить решение компилятора:

`go build -gcflags="-m" ./...` //Сообщение `escapes to heap` - объект будет размещён в heap.
