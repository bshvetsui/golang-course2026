основной способ коммуникации горутин без мьютексов
```
ch := make(chan int)    // без буфера
ch := make(chan int, 3) // с буфером на 3 элемента

ch <- 10 // отправить
x := <-ch // получить
close(ch) // закрыть 

for v := range ch {
    fmt.Println(v)
} // читать до закрытия
```
- **Без буфера (make(chan T))** — передача **из рук в руки**.
- **С буфером make(chan T, N)** — Имеет буфер на `N` элементов, передача **через очередь**. Буфер устроен как кольцо, sendx показывает куда писать след. элемент, recvx показывает откуда читать след. элемент. Как только любой из индексов доходит до конца - он переходит в начало

Канал представлен структурой рантайма **hchan**:
1. qcount — количество элементов в буфере
2. dataqsiz — размер буфера (cap)
3. buf — указатель на кольцевой буфер
4. elemsize — размер одного элемента
5. closed — флаг закрытия
6. sendx — индекс для записи
7. recvx — индекс для чтения
8. recvq — очередь ожидающих получателей (sudog)
9. sendq — очередь ожидающих отправителей
10. lock — мьютекс
## select - позволяет ждать сразу несколько операций с каналами, выполнит тот `case`, который первым станет готов
```
select {
case x := <-ch1:
    fmt.Println(x)

case y := <-ch2:
    fmt.Println(y)
    
default: 
	fmt.Println("данных нет") 
}
//Если первым придёт значение в `ch2`, выполнится второй `case`
// Если ни один канал не готов, выполняется `default`
```
## nil канал - нужен чтобы на время отключить один `case`
```
var ch chan int // nil - создается без make и не имеет ничего от hchan

select {
case v := <-ch:
    fmt.Println(v) // никогда не выполнится
default:
    fmt.Println("нет данных")
}
```
1. Закрытый канал - отправка = panic, получение = false, повторное закрытие = panic
2. nil канал -  отправка = блок навсегда, получение = блок навсегда, закрытие = panic
