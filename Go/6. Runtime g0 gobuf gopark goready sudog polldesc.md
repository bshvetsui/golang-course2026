## g0 - служебная горутина
на ней выполняется весь рантайм, хранит стек **8KB** на который можно переключится через **mcall**
1. `schedule()` — **решает кого запускать**. Сначала ищет горутину через findRunnable() и потом через execute() (низкоуровн. - gogo()) передает новую горутину процессору.
2. GC и stopTheWorld(), mallocgc() 
3. netpoll (epoll)

каждый поток имеет свой g0, который перехватывает управление на себя при:
1. gopark - горутина заснула 
2. goexit - завершилась
3. Gosched (горутина сама передает управление g0)
4. Любой syscall. Застрявшие sysmon сам замечает, он всегда висит на отдельном потоке.
## gobuf - сохраненный контекст горутины при переключении
хранит:
1. **Stack Pointer**— указатель на вершину стека горутины.
2. **Program Counter** — адрес инструкции, с которой нужно продолжить выполнение.
3. **G** — указатель на саму горутину.
## gopark 
1. Помечает горутину как `_Gwaiting`
2. Запоминает почему уснула - **waitreason**:
	1. chan recieve/ chan send - ждет или вписывает данные в/из канала
	2. select - ждет одно из нескольких событий
	3. semaquire - ждет освобождения от блокировки
	4. IO - ждет операцию ввода/вывода
	5. sleep - спит по таймеру time.Sleep
3. отдает управление планировщику schedule()
4. Освободившийся поток берет в работу другую горутину
## goready 
1. находит спящую горутину и помечает `_Grunnable` 
2. Добавляет в очередь - обычно в runnext
3. если ее некому выполнять - будит поток через **wakep**

## Кто взывает gopark и goready?
1. Каналы - чтение из пустого или запись в полный канал
2. **sync примитивы** - Mutex, WaitGroup, Cond и другие
3. select - ожидание сразу нескольких каналов
4. Ожидание I/O - пока сокет не станет готов к чтению или записи
5. time.Sleep

## sudog - обёртка вокруг горутины  связывающая ее с операцией синхронизации. ТОЛЬКО ДЛЯ sync и каналов
хранит: 
1. **g** — указатель на ожидающую горутину.
2. **elem** — указатель на передаваемые данные (например, элемент канала).
3. **next / prev**— ссылки для включения в очередь ожидания.
4. ***c*** — указатель на канал (для операций с каналами).

## pollDesc - обёртка на каждом сокете, которая знает какую горутину будить если можно будет читать или писать (I/O)
ей управляет **netpoll()** через **schedule()** в процессе поиска findRunnable() или **sysmon** периодически вызывает тот же **netpoll()**. Сама функция вызывает epoll_wait и получает список готовых fd
содержит:
1.  2 **атомарных** поля: rg(read goroutine) и wg (write goroutine) в зависимости от того что они делают, которые содержат 3 значения на выбор: **pdReady (данные готовы), pdWait (ждём), указатель на запаркованную G**
2. fd - файловый дескриптор (адрес открытого сокета для передачи I/O, обычное число)
3. atomicInfo - атомарные флаги состояния (нужны чтобы GC и runtime правильно работали с атомарно изменяющимися полями)
