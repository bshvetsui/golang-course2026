## 1. Под падает или не стартует

Признаки: `CrashLoopBackOff`, `Error`, растёт `RESTARTS`.

```bash
kubectl get pods -n prod // -n означает namespace, здесь это прод 
kubectl describe pod <pod> -n prod
kubectl logs <pod> -n prod --previous
```
Ищем причину падения:
1. Panic или ошибка приложения.
2. `OOMKilled` (Ядро убило процесс потому что хочет слишком много памяти)
3. Ошибка подключения к БД/API.
4. Неправильный конфиг или Secret.
5. Ошибка health-check (startupProbe, livenessProbe, readinessProbe)

`describe` показывает, почему Kubernetes не может запустить или удержать под.  
`logs --previous` показывает логи предыдущего упавшего контейнера.
## 2. Под работает, но сервис ведёт себя неправильно
Признаки: `STATUS: Running`, `RESTARTS: 0`, но есть ошибки, тормоза или странное поведение.
```bash
kubectl logs <pod> -n prod -f — смотреть текущие логи.
kubectl top pod -n prod  — проверить CPU и память.
```

Используем
1. Grafana/Prometheus — latency, error rate, RPS, ресурсы во времени.
2. Kibana/Loki — искать ошибки в логах за нужный период.
3. Tracing — искать медленные запросы между сервисами.
## 3. Приложение не задеплоилось
Признак: pipeline упал до создания или обновления подов.
Проверяем логи в GitLab'e 
# Дебаг GitLab CI Job

## 1. Находим неисправную job

```text
GitLab → CI/CD → Pipelines → нужный pipeline
```
## 2. Если job красная — `failed`
1. Открываем job и смотрим лог. Внизу обычно будет:
```text
ERROR: Job failed: exit code 1
```
Это не причина, а только итог. Ищем выше **первую конкретную ошибку**:
```text
command not found
permission denied
file not found
tests failed
build failed
unauthorized
connection refused
```
2. После этого смотрим, какая команда упала в .yml файле:
```yaml
script:
  - npm ci
  - npm test
  - npm run build
```
Например, если ошибка появилась после `npm test`, чинить нужно тесты или тестовое окружение, а не GitLab.
## 3. Запускаем упавшую команду локально
### Go backend
```bash
go mod download
go test ./...
go build ./...
golangci-lint run
```
### Node.js backend / Frontend
```bash
npm ci
npm run lint
npm test
npm run build
```
Если локально команда тоже падает — проблема в коде или зависимостях.
Если локально работает, а в GitLab падает — сравниваем окружение CI и локальной машины.
## 4. Типовые причины красной job
### `command not found`
```text
golangci-lint: command not found
npm: command not found
docker: command not found
```
Причины:
1. Неправильный Docker image.
2. В image нет нужной программы.
3. Программа не установлена в `before_script`.
4. Неправильный `PATH`.
Исправление:
```yaml
image: golang:1.24
или 
before_script:
  - npm install
```
## 5. Ошибка зависимостей
### Go
```text
missing go.sum entry
module not found
authentication required
```
Проверяем:
```bash
go mod tidy
go mod download
```
Причины:
1. Не закоммичен `go.sum`.
2. `go.mod` и `go.sum` не совпадают. (`go.mod` хранит список зависимостей и их версии, а `go.sum` — контрольные суммы скачанных зависимостей для проверки, что они не изменились.)
3. Нет доступа к приватному репозиторию.
4. Не настроен `GOPRIVATE`.
### Node.js / frontend
```text
package.json and package-lock.json are not in sync
ERESOLVE
401 Unauthorized
```
Проверяем:
```bash
npm install
npm ci
```
Причины:
1. Не обновлён `package-lock.json`.
2. Конфликт зависимостей.
3. Нет токена для приватного registry (это там где хранятся пакеты которые используются. Самый популярный Nexus монорепозиторий).
4. Другая версия Node.js или npm.
## 6. Упали тесты
```text
FAIL
Test failed
ECONNREFUSED
connection refused
```
Причины:
1. Сломан тест.
2. Не поднята БД, Redis или другой сервис.
3. Нет env-переменных.
4. Не выполнены миграции.
5. Тесты конфликтуют при параллельном запуске.

Пример GitLab service:
```yaml
services:
  - name: postgres:17
```
Проверяем, что приложение подключается по имени service, а не через `localhost`.
## 7. Упала сборка
### Go
```text
undefined
cannot use
imported and not used
```
Причины:
1. Ошибка компиляции.
2. Не сгенерированы mocks, protobuf или sqlc.
3. В CI другая версия Go.
4. Различается регистр имени файла.
5. Не хватает системных библиотек для CGO.
### Node.js / frontend
```text
TS2307: Cannot find module
Type error
Build failed
heap out of memory
```
Причины:
1. Ошибка TypeScript (проверки типов).
2. Неправильный импорт.
3. Не установлена зависимость.
4. Не сгенерирован Prisma Client.
5. В CI другая версия Node.js.
6. Runner не хватает памяти.

## 8. Нет переменной окружения

```text
DATABASE_URL is not set
JWT_SECRET is missing
authentication required
```
Проверяем в Гитлабе:
```text
Settings → CI/CD → Variables
```

Причины:
1. Переменная не создана.
2. Ошибка в названии.
3. Переменная `Protected`, а ветка обычная.
4. Переменная доступна только другому environment.
5. В Merge Request из fork секреты недоступны.
Секреты нельзя печатать в лог для проверки, можно проверить только наличие:
```bash
test -n "$DATABASE_URL" || exit 1
```

## 9. Job висит в `pending` или `stuck`
Это обычно не ошибка кода.
Причины:
1. Нет активного Runner.
2. Runner занят.
3. Не совпадают `tags`.
4. Runner запрещён для текущего проекта.
5. Protected Runner не запускает обычную ветку.

Сравниваем:
```yaml
job:
  tags:
    - docker
```

с тегами Runner в настройках GitLab.

## 10. Job работает слишком долго

Причины:
1. Тест или скрипт завис.
2. Приложение ждёт БД.
3. Команда ждёт пользовательский ввод.
4. Завис скачивается слишком долго.
5. Deploy ждёт готовности Pod.
6. Нет timeout у сетевого запроса.

Добавляем подробный вывод:
```bash
go test -v ./...
npm test -- --runInBand
docker build --progress=plain .
```

И ограничиваем время:
```yaml
job:
  timeout: 15m
```
## 11. Упал Docker build
```text
COPY failed
no such file or directory
unauthorized
no space left on device
```
Причины:
1. Неправильный путь в `COPY`.
2. Файл исключён через `.dockerignore`.
3. Ошибка `go build` или `npm ci` внутри Dockerfile.
4. Нет доступа к Registry.
5. На Runner закончилось место.
6. Собирается неправильная архитектура.

Запускаем локально:

```bash
docker build --progress=plain .
```

## 12. Упала deploy job, САМАЯ ВАЖНАЯ

```text
Unauthorized
Forbidden
release failed
context deadline exceeded
```
Причины:
1. Неверный `KUBECONFIG`.
2. Нет RBAC-прав.
3. Ошибка Helm values.
4. Не существует namespace.
5. Не найден Docker image.
6. Новый Pod не может запуститься.
7. Deploy превысил timeout.
Если job дошла до Kubernetes:
```bash
kubectl get pods -n prod
kubectl describe pod <pod> -n prod
kubectl logs <pod> -n prod --previous
```
