В больших компаниях обычно есть центральный репозиторий с CI/CD-шаблонами, а в каждом приложении лежит маленький `.gitlab-ci.yml` который только подключает нужный шаблон и передаёт параметры
## Как это выглядит в Гитлабе 
```
platform/ci-components
├── templates/
│   ├── frontend.yml
│   ├── node-backend.yml
│   ├── go-backend.yml
│   ├── docker-build.yml
│   └── deploy-kubernetes.yml
└── .gitlab-ci.yml
```
DevOps/Platform-команда поддерживает этот репозиторий, тестирует изменения и выпускает версии

А уже в репозитории команды разработчиков в ci yaml 
```
include:
  - component: gitlab.company.local/platform/ci-components/frontend@1.4.2
    inputs:
      node-image: node:22-alpine
      install-command: npm ci
      build-command: npm run build
      output-directory: dist
```
`inputs` — просто параметры шаблона, чтобы была возможность что то поменять если разработчикам надо
