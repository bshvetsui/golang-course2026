1. **Composite (Компоновщик)** — часть и группа имеют общий интерфейс, поэтому строится дерево. Пример: несколько `Handler` можно объединить в общий роутер

2. **Decorator (Декоратор)** — оборачивает объект и добавляет ему поведение. Классический пример — middleware: `Handler → Auth → Logging → Metrics`.

3. **Facade (Фасад)** — простой интерфейс скрывает несколько действий внутри. Например `OrderService.Create()` внутри делает валидацию → запись в PostgreSQL → отправку события, а handler вызывает один метод `Create()`.

4. **Adapter (Адаптер)** — приводит один интерфейс к другому. Пример: В своём коде аналогично можно обернуть библиотеку под свой интерфейс.

5. **Bridge (Мост)** — отделяет абстракцию от конкретной реализации. Хороший пример — `database/sql`: код работает через общий API, а конкретная PostgreSQL реализация подключается отдельно через driver.

6. **Flyweight (Приспособленец)** — общий тяжёлый объект переиспользуется многими частями программы вместо создания копии для каждого. Например один `pgxpool.Pool`, config или HTTP client используется множеством handler/service 

7. **Proxy (Заместитель)** — посредник с тем же назначением, который контролирует обращение к реальному объекту. Например `ReverseProxy`: `client → proxy → backend`. В приложении proxy может добавить cache, retry, rate limit перед настоящим сервисом.

8. **Front Controller (Единая точка входа)** — все запросы сначала проходят через одно место. В Go это router/`ServeMux`: `HTTP request → router → middleware → нужный handler`.
