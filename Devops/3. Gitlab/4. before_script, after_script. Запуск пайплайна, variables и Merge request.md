 `before_script` - выполняет команды перед основным скриптом каждой job
 `after_script` - выполняет команды после основного скрипта каждой job

**before_script:**
1. Выполняется в той же shell-сессии, что и script
2. Если завершается с ошибкой, job помечается как failed
3. Переменные, установленные здесь, доступны в script
4. Если переопределить переменную здесь, то в script она тоже поменяется

**after_script:**
1. Выполняется в отдельной shell-сессии
2. Всегда выполняется, даже если script завершился с ошибкой
3. Переменные из script и before_script недоступны
4. Не влияет на статус job
## Запуск пайплайна
**1. Rules (рекомендуемый способ)**
```yml
deploy_job:
  script:
    - echo "Deploying to production"
  rules: # здесь уже описываем когда запускать пайплайн
   - changes:
        - "frontend/**/*" #если в этой папке что то поменялось то запускаем
        - "package.json" #если в этом файле поменялось - тоже
    - if: '$CI_COMMIT_BRANCH == "main"'
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"' # ВАЖНО! Запускать на merge request
      when: manual
    - when: never
```
### Встроенные переменные
1. `$CI_COMMIT_BRANCH` - название текущей ветки
2. `$CI_PIPELINE_SOURCE` - источник запуска пайплайна
3. `$CI_COMMIT_TAG` - тег коммита
4. `$CI_MERGE_REQUEST_TARGET_BRANCH_NAME` - целевая ветка MR

**2. Через `when`**
1. `when: always` - всегда выполнять
2. `when: on_success` - только при успехе предыдущих job (по умолчанию)
3. `when: on_failure` - только при провале предыдущих job
4. `when: manual` - запуск вручную
5. `when: never` - никогда не выполнять
