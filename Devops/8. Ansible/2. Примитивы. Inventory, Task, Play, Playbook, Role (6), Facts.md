1. **Инвентарь (Inventory)**
   cписок хостов, может быть статичным в виде текcтового файла в формате `.ini` или динамическим в виде скрипта или плагина, который подгружает структуру данных из стороннего источника, например, Openstack API или база LDAP.
```
[web]
nginx01
nginx02
nginx03

[postgresql]
postgresql01
postgresql02
postgresql03

[prod:children]
web
postgresql

[devel]
dev-nginx01
dev-postgresql01
```
2. **Задание (Task)**
    атомарная операция, выполняемая на управляемом хосте, например apt install nginx:
```
    apt:
  package: nginx
  state: present
```
3. **Сценарий (Play)** или **Плейбук (Playbook)**
	сценарий или скрипт, содержащий одно или несколько заданий на выполнение, например apt install nginx и потом в консоль выводим whoami:
```
$ cat prod-playbook.yml
---
- hosts: nginx
  tasks:
    - apt:
        package: nginx
        state: present
    - shell: whoami
```
4. Роль (Role)
	более сложная абстракция, выглядит как структура директорий и файлов, которые описывают набор дефолтных переменных, зависимостей от других ролей, может содержать файлы и темплейты, содержит задания(Tasks).
Роли имеют свою структуру каталогов, которая выглядит так:
```
rolename
 - files # файлы которые будут скопированы на настраиваемые хосты
 - handlers # как функции которые можно вызвать в процессе через "notify: name"
 - meta # информация о роли, версия, название и тп.
 - templates # шаблоны .conf файлов куда можно вставлять переменные ансибла
 - tasks # описать основные действия, скрипт где все используется
 - vars # переменные: порты, max подключений и тп
```

5. **Факты (Facts)**
	структура данных, которая содержит информацию о хосте, например, версию дистрибутива, IP адреса и файловые системы. Ansible забирает эту информацию с хоста, и на нее можно ссылаться в коде плейбуков и ролей.
