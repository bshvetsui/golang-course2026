
**Affinity** — более гибкий аналог `nodeSelector`. Позволяет задавать условия, **на каких Node запускать Pod**, а также рядом с какими другими Pod'ами его размещать.

**Anti-Affinity** — наоборот, позволяет указать, **рядом с какими Pod'ами его размещать не нужно**.
 Есть три основных типа:
1. `nodeAffinity` — правила выбора **Node**.
2. `podAffinity` — размещать Pod рядом с определёнными **Pod'ами**.
3. `podAntiAffinity` — размещать Pod отдельно от определённых **Pod'ов**.

```yaml
affinity:

  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      # required — обязательное условие при планировании Pod'а.
      # IgnoredDuringExecution — после запуска Pod не будет перемещён,
      # если labels Node изменятся.
      nodeSelectorTerms:
        - matchExpressions:
            # На Node disktype не должен быть hdd
            - key: disktype
              operator: NotIn
              values:
                - hdd

            # Значение label memory должно быть больше 8
            - key: memory
              operator: Gt
              values:
                - "8"

            # На Node должен существовать label gpu
            - key: gpu
              operator: Exists


  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
      # preferred — желательное, но не обязательное правило.
      # weight задаёт важность правила от 1 до 100.
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchExpressions:
              - key: app
                operator: In
                values:
                  - web-app

          # Не размещать web-app Pod'ы на одном хосте
          topologyKey: kubernetes.io/hostname


  podAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchExpressions:
            # Разместить Pod на том же хосте,
            # где уже есть Pod с security=s1
            - key: security
              operator: In
              values:
                - s1

        topologyKey: kubernetes.io/hostname
```

`required...` — **жёсткое требование**: если условие выполнить нельзя, Pod не запустится.

`preferred...` — **пожелание**: scheduler постарается выполнить условие, но может его проигнорировать.

`topologyKey` определяет уровень, на котором сравниваются Pod'ы. Например, `kubernetes.io/hostname` означает **одна конкретная Node**.
