### Ingress 
это конфигурация. Она нужна чтобы описывать как сервисы общаются.
Backend сегодня разбит на микросервисы. И им нужно общаться через что то, потому что сервисы не знают кто где лежит, а в Ingress эта информация хранится
Другими словами - Ingress описывает маршрутизацию. Вот пример:
```yml
kind: Ingress # Тут мы выбираем ingress 

spec:
  ingressClassName: config-prikolov # ПРИВЯЗКА К Ingress Controller. Читай НИЖЕ
  rules:
    - host: example.com
      http:
        paths: # здесь расписано куда идти 
          - path: /api           # Например если сервис делает запрос в /api
            pathType: Prefix
            backend:
              service:
                name: api-service # Значит он хочет общаться с подами с                                              именем api-service
                port:
                  number: 80

          - path: /static
            pathType: Prefix
            backend:
              service:
                name: static-service
                port:
                  number: 80
```

### Ingress Controller
Нужен для управлению этими самыми конфигами. Разворачивается в деплойменте с парой подов, и мониторит ситуацию. Подключить Ingress к Ingress Controller можно через IngressClass:
```yml
kind: IngressClass
metadata:
  name: config-prikolov # ТОЖЕ САМОЕ что в Ingress прописали смотри ВЫШЕ
spec:
  controller: company.com/nginx-controller # здесь мы подключаем контроллер
```
