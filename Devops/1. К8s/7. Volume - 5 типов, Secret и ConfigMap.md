это абстракция файлового хранилища, которая живет с подом. Этот диск может быть:
1. `ConfigMap` — набор файлов конфигурации .conf
2. `Secret` — секретные файлы/данные. Обычно используют Vault вместо него. **kubelet** использует секреты для **подключения к апи серверу**, для загрузки образов из docker registry
3. `emptyDir` — временная директория, живущая пока жив Pod.
4. `PVC` — постоянное внешнее хранилище.
5. `hostPath` — папка на узле уже существует, и подключается к подам. Данные не пропадают после удаления пода.
## ConfigMap
Конфигурация .conf - это этакое хранилище параметров.
Вот пример создания:
```yml
kind: ConfigMap # выбираем тип
data:
  default.conf: | # здесь начинается конфиг
    server {
      listen 80 default_server;
      server_name _;
      default_type text/plain;

      location / {
        return 200 'Hello from $hostname\n';
      }
    }
```
А тут мы вставляем в поды 
``` yml
apiVersion: apps/v1
kind: Deployment
metadata:
	  name: my-deployment

spec:
  replicas: 2

  selector:
    matchLabels:
      app: my-app

  template: ## вот здесь начинается образец подов в деплойменте. Даем поду конфигмап через volumes
      volumes:
        - name: config
          configMap:
            name: my-configmap
```
ConfigMap можно передать поду через:
1. дать через volume (наш пример)
2. через переменные среды env
3. параметры запуска контейнера (--env=prod тянет за собой .conf оттуда)
